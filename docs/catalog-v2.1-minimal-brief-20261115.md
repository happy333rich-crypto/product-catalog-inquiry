## 1. 產品定位與視覺原則
「好找商品、看懂規格、方便把這一支產品傳給業務」。不是電商、品牌官網，也不靠強迫填表提高使用率。
- 手機優先，白底乾淨、有辨識度的商品圖，字體易讀，按鈕易點。
- 以現有 V2 的色彩、字體、間距、圓角為準；避免整站重設計。
- 不加「主推／新品／促銷」等標籤，不顯示價格、庫存、進價、毛利、內部資訊。
- 商品圖片務必沿用**既有 repo / 已授權 Google Drive 圖片**；本輪不去網路找圖。

## 2. 核心操作流程
### A. 看圖／看規格
原有品牌分類、搜尋、商品列表、商品詳情照常使用。

### B. 單一商品「分享商品／傳 LINE 詢問」（P1）
- 在商品詳情頁，提供主要操作按鈕：`分享商品／傳 LINE 詢問`。
- 產出精簡、無價格的分享內容：品名、商品編號、規格、箱入數、可直達該商品的網址（既有 hash `#product=SKU`）。
- 在支援分享的手機上使用原生分享介面，可讓客人自行選 LINE；不能宣稱網站會自動傳到指定業務 LINE。
- 在不支援原生分享或分享失敗時，提供**明確的複製資訊／連結** fallback；避免分享被取消時誤報成功。
- 分享內容與網址須能在另一台手機打開正確商品頁。不得要求填店名／聯絡人／電話。

### C. 單一商品「儲存商品資訊圖」（P1）
- 商品詳情頁提供次要操作：`儲存商品資訊圖`。
- 產生易讀的直式或接近方形圖卡：**產品原照、完整品名、規格、箱入、SKU**；若文字過長須自然換行，不可截斷貨號。
- 只使用同源的現有商品圖片。可用 Canvas 產圖，但要處理跨裝置載圖、圖片未就緒、canvas `toBlob` 失敗。
- 手機若無法直接下載，應提供可預覽／長按儲存的圖片或其他合理 fallback；不可呈現無作用按鈕。桌機提供下載。
- 缺圖商品提供純文字資訊圖，明確標示「尚無商品圖片」，不要拿其他 SKU 的圖代替。

### D. 多品詢價清單簡化（P1）
- 原有增減箱數、移除商品、清空、暫存等操作保留。
- **可不填任何客戶資料**，直接生成／分享含 SKU、品名、規格、箱入、數量的清單。
- 店名、聯絡人、電話、地區與備註全部為選填；若有填寫則附在輸出文字內。不得靜默上傳。
- 若商品清單為空，明確提示，不允許送出空清單。
- 仍保留原本「分享／複製」能力；桌機無原生分享時可複製。
- 表單修改後既有暫存應相容，避免舊用戶資料造成例外。

## 3. 明確不做
- 不開會員／登入、不介接金流／ERP／庫存／客戶資料庫、不建價格系統。
- 不改品牌分類、商品來源檔、不新增產品、不補 6 項缺圖。
- 不做重構、不換網站框架，不重新製作所有商品圖。
- 不加入外部圖片搜尋或大量爬取。

## 4. 開發順序與驗收
1. **先提交視覺與互動方案（可用簡單 mockup）**，等對照既有介面確認改動範圍，再實作。
2. 拆成小提交：單品分享、資訊圖、詢價簡化與裝置相容；避免一次重寫。
3. 在獨立 V2.1 分支完成實作和本機測試；先使用 preview / local，**不能直接覆蓋正式站**。
4. 核對至少以下情境：iPhone Safari、Android Chrome、LINE 內建瀏覽器（可實測時）、桌機；單品分享、原生分享拒絕／缺少、文字複製、產圖、缺圖、長名稱、再次開啟商品頁、多品清單與空清單。
5. 驗收後再明確決定是否部署。保留 V2 基準做回退。

## 5. Codex 額度使用規則
- 前期由 ChatGPT 直接讀 repo、整理規格與修改清單，**不把搜尋／核對／反覆規劃丟給 Codex**。
- Codex 執行時一律限定本規格、改動檔案及必要驗收，不准自行擴大需求、查找圖片或重複部署。
- 確認之前已測項目就引用驗收紀錄，只對受影響範圍回歸測試。若存在阻礙先回報。
